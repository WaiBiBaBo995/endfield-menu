# Endfield Menu 1.5.0 验证记录

日期：2026-10-25。目标为保留原 HTML/AUI 输入和画面，同时降低解码及闲置成本。
**稳定 60 FPS 尚未达成，不能把本版描述为全面帧率提升或低内存保证。**

## 环境和统计口径

- Windows 11 x64，i7-13620H，15.78 GiB RAM，RTX 4060 Laptop 8 GiB。
- Java 21.0.11，MC 1.21.1，NeoForge 21.1.251，AUI 1.2.8，WebView2 155.0.4283.62。
- 独立 `endfield-qa` 世界，视距 6，模拟距离 5，关闭 VSync，游戏上限 120 FPS。
- 同机先后运行 1.4.2 基准与优化版；1080p / 1440p 阶段各约 30 秒，5 秒采样。
- HTML FPS 统计实际呈现的不同完整网页帧，和游戏 FPS 分开。下表为阶段内采样值中位数；
  P95 是每次采样窗口的 P95 再取中位数，**不是所有原始帧合并后的全局 P95**。
- 解码耗时包括 Base64、图像头检查、像素解码等该段工作；不是只有原生函数本身。
- 帧年龄为浏览器帧时间戳到上传的时间，含捕获/传输/解码/调度。
- 首帧从菜单 init 到首个匹配当前 epoch 的可用图像，不等于完整 900ms 动画结束。

## 1.4.2 与优化版对照

| 窗口 / 指标 | 1.4.2 | 1.5.0 长测构建 |
|---|---:|---:|
| 1920×1080 HTML FPS | 74.71 | 64.38 |
| 1920×1080 HTML 帧间隔 P95 | 25.72 ms | 31.76 ms |
| 1920×1080 解码段 | 10.36 ms | 6.14 ms |
| 1920×1080 帧年龄 | 47.60 ms | 40.12 ms |
| 1920×1080 游戏帧间隔 P95 | 10.27 ms | 11.58 ms |
| 2560×1440 HTML FPS | 54.40 | 57.16 |
| 2560×1440 HTML 帧间隔 P95 | 30.33 ms | 36.15 ms |
| 2560×1440 解码段 | 22.96 ms | 14.07 ms |
| 2560×1440 帧年龄 | 90.51 ms | 92.59 ms |
| 2560×1440 游戏帧间隔 P95 | 14.20 ms | 16.24 ms |
| 首次打开首帧（同一会话，跨 resize 不重置） | 170.49 ms | 273.41 ms |

解码段中位数下降约 41% / 39%，但浏览器绘制、JPEG 编码与帧传输仍是主要限制。
1080p 这次配对测量反而更慢，1440p 平均网页吞吐仅小幅提高，尾部帧间隔也未改善。
两次运行并非并行锁定硬件状态，且只有一次配对，不能据此宣称统计显著的整体提升。

最终发行源码的完整输入回归，热身后约 70.53–74.98 HTML FPS，首帧约 84–177ms；
重新进入世界后为 79.07 HTML FPS / 首帧 149.51ms。
最终回收专项运行初始约 71.53 HTML FPS / P95 26.73ms / 首帧 221.49ms，
也不符合每帧 16.7ms 的稳定目标。具体记录随工程提供。

输入延迟指标只测 **DOM 收到输入 → 对应元数据帧上传**，不能代表硬件到屏幕延迟。
最终隔离专项用 MC/GLFW 回调执行地图按下、拖动、松开，观察到 DOM→上传
P50/P95 均为 85ms。这里只有极少数动作，不是统计充分的输入延迟分布。
完整输入回归在切换屏幕后清空激活前样本，所以日志中的 -1 代表该轮无样本。
旧输入回归记录有跨激活时间戳污染，其中异常数值不作为性能结论；
发行源码已排除激活前的时间戳。

## 内存与 15 分钟长测

优化版连续 900.01 秒，完成 100 次菜单开关、10 次世界往返，最后在世界中闲置。
配置按钮轮换五个分辨率、默认回收、低内存关闭与重载断言通过。
基准也完成 100/10/900 秒，但其旧 QA 在最终闲置段意外重新打开菜单，且
外部内存采样约第 241 秒才开始，因此缺少基准启动/初次打开的进程内存，
**不能把最终闲置占用作为严格同状态的 A/B 降幅**。

| 优化版状态 | 游戏进程 Private Bytes | 专属 WebView2 进程 Private Bytes 合计 |
|---|---:|---:|
| 初始 1080p 菜单采样范围 | 2276–2287 MiB | 459–947 MiB |
| 1440p 菜单采样范围 | 2350–2400 MiB | 540–787 MiB |
| 100 次连续开关阶段峰值 | 2396 MiB | 1876 MiB |
| 低内存超时后 | 约 2684–2791 MiB（含整套 MC） | 0，专属浏览器退出 |
| 最终闲置段起点 → 终点 | 2854 → 2714 MiB | 1166 → 347 MiB |
| 全程观察峰值 | 2938 MiB | 1876 MiB |

专属浏览器按本模组 profile 和子进程识别；Private Bytes 相加，**未把各进程
working set 直接相加当作独占物理内存**。游戏进程数字包括 MC、世界、JVM、AUI
等全部成本，不能归因于本菜单。采样为约 5 秒一次，瞬时峰值可能遗漏。

优化版 JVM 峰值：used heap 1259 MiB、committed heap 1336 MiB、JMX direct
91.68 MiB。最终 used heap 569.5 MiB，JMX direct 91.25 MiB。JMX 不覆盖
本模组 `memAlloc`，因此另记流缓冲计数。最终网页 GPU 纹理、帧接收缓存、
流原生像素缓冲与池均为 0；地形和磨砂目标销毁。

Windows GPU 进程计数器观察到游戏 dedicated 峰值约 404.5 MiB；该计数器可能
在多个上下文重复归属，且采样较稀疏，不能用作精确显存总量或泄漏证明。
浏览器 GPU 缓存由 WebView2 管理，保留浏览器时不会保证立即释放所有显存。

开关第 0–24、25–49、50–74、75–99 次的浏览器 Private Bytes 中位数为
1704 / 1668 / 1778 / 1703 MiB，没有随每个分段单调增加；但峰值仍高。
15 分钟不够证明不存在长期泄漏，默认保留浏览器仍会常驻数百 MiB。
低内存模式是明确降低此常驻成本的选项，代价是重新加载。

最后新增的隐藏 viewport 缩小逻辑在长测之后加入，另由最终专项验证重开，
不能把这次长测的内存数据误写为缩小 viewport 后的测量。

## 画面、兼容和未通过的实验

- 原 `index.html` 和 20 个组件逐字节校验通过；只改独立 MC 适配层。
- AUI 1.2.8 JAR 哈希保持 `7636AE43311B5401B13776799FB79CF4122B23DB7FE4AE6CA03A94B14ACBC0F6`，未改 JAR/DLL。
- 保留 AUI 真鼠标、拖动、滚轮、键盘，原生地形/海拔线/玩家扫描光与实时 GPU 磨砂。
- 900ms / 520ms 动画保留；长测退出观测值 522.62ms，受帧调度影响。
- 元数据移到显示图像外的 64px 条带；头像区域排除色键，实际纯绿头像合成像素
  `ff01ff00`，未被去除；未就绪仍为深灰。
- 独立 DLL 用 libjpeg-turbo SIMD / libspng + zlib-ng；仅解码，仍需 CPU 传输和 GPU 上传。
- 双平面真实 alpha 原型静止误差很小，但动画 alpha 平均误差最高 8.73/255、
  超过 8/255 的像素约 13.58%，且约 39–43 FPS，所以不进入发行链路。
- 默认 JPEG 仍是近似透明恢复：其他绿色素材、半透明边缘与原始 HTML 会有误差。
  PNG 模式提供真实 alpha，不能兼得这条链路下的 JPEG 吞吐。
- 当前 AUI 未暴露可用的共享 GPU 纹理/浏览器控制器，零拷贝链路未实现。
- WebView2 退出仍偶有 `Chrome_WidgetWin_0 / 1411` 警告；未观察到对应崩溃。
- 自动测试通过实际 MC/GLFW handler，未完成不同鼠标硬件/光影包/显卡上的兼容认证。

## 复现与原始证据

```powershell
.\gradlew.bat build sourceBundle --offline
.\gradlew.bat runClient --offline -PruntimeQa -PqaWidth=1920 -PqaHeight=1080
.\gradlew.bat runClient --offline -PruntimeQa -PfinalQa -PqaWidth=1920 -PqaHeight=1080
.\gradlew.bat runClient --offline -PruntimeQa -PoptimizationQa=custom -PqaWidth=1920 -PqaHeight=1080
python tools/qa/memory-watch.py custom
```

QA 会使用独立 `endfield-qa` 存档、调整开发实例视频设置并自动退出；不能在实际
游玩的实例中运行。`-PoptimizationQa` 需要 QA 存档已经存在。
独立 QA 源集不会打进发行 JAR。离线需先具备依赖缓存。

`qa-1.5.0/` 包含原始 JSONL、筛选日志与聚合 JSON。`tools/qa/report.py`
从原始测量再生成统计；源文件路径记录在脚本中。截图见 `screenshots/`。
最终专项、PNG 与最终输入回归结果见下节。

## 最终源码回归完成记录

- `final-input.log`：46 项 PASS，无 QA FAILED；包含设置、背包、进度、统计、
  地图拖动/滚轮/复位、右列表拖动/滚动、视差、真实 Esc、GUI 缩放、窗口缩放、
  连续动画、同浏览器复用、帧流中断后 AUI 输入、动态背景、世界重连。
- `final-cache-resolutions.log`：27 项 PASS，DONE；默认隐藏 65 秒后网页 GPU/
  地形/磨砂资源销毁，同一浏览器保留并能恢复帧流。五个分辨率预设均验证实际
  raster、纯绿头像像素，以及 MC/GLFW 鼠标点击打开设置。包括 3840×2160。
  该脚本末尾刚从设置返回又立刻退出，因此最后一条 `firstDrawMs=-1`、
  `completeFrames=0` 是新一轮尚未绘制的统计，不能作为重开失败或 4K 吞吐。
- `final-png.log`：6 项 PASS；PNG 透明模式有完整帧、正确地图投影、不使用色键，
  `libspng-zlib-ng` 生效。1080p 短测网页 32.96 FPS、P95 60.48ms、首帧 160.71ms，
  明显慢于 JPEG；该结果是冒烟测试，不是 PNG 的 15 分钟长测。
- `final-input-timing.log`：地图真实 handler 输入，DOM→上传延迟样本 85ms，
  确认指标能在同一激活期记录；它不包含鼠标硬件和最终显示扫描延迟。
- 17 项单元测试通过，原页面和 20 个组件逐字节校验通过。

首轮最终专项受到桌面额外输入干扰，首轮输入回归又因 QA 屏蔽回调影响了
窗口缩放后的 AUI 输入。随后恢复普通完整回归的原有回调，46 项通过；
最终回收专项在固定窗口下隔离桌面输入并调用真实 handler，27 项通过。
未把失败尝试计入通过数量。
另一次延迟测试沿用完整回归时被桌面输入打断，改为固定窗口隔离专项后完成，
没有将那次未完成记录替换已通过的 46 项完整回归。
